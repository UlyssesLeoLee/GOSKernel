# ADR-005：`graph_topo_indices*` 家族 — Snapshot-Release 重构

> 完整文档：[ADR-005 全文](../../../03_详细设计/ADR-005-topo-indices-snapshot-refactor.md)
> 关联：[[架构决策索引]] · [[ADR-004 可见性语义]]

## 一句话

`graph_topo_indices` 到 `graph_topo_indices22`（共 22 个函数，无编号版起算），
全部违反了 `gos-topology-snapshot-pattern` skill 确立的规则：应该"锁定 →
快照 → 释放 → 计算"，实际做的是"锁定 → 计算 → 释放"，把 O(V×E) 的整个计算
过程都持锁跑完。

## 为什么重要

- `RUNTIME` 是 `spin::Mutex`，不禁用中断。
- `post_irq_signal()`（中断上下文）也要 `RUNTIME.lock()`。
- 同核心中断在持锁计算期间触发 → ISR 自旋等锁 → 持锁方被中断、永远无法恢复
  → **内核死锁**。
- 这个 bug 类别在 katz/pagerank/hits/community 上真实发生过、已修复
  （CodeRabbit comment 3515944030）；`topo` 家族是唯一被系统性遗漏的部分，
  历经 19～22 轮自动强化循环都未被发现。

## 发现过程

在给 `topo19`（V3.30，Reverse Wiener Λ + RCW + Terminal Wiener TW）做
10-角度并行 self-review 时被两个独立 agent（lock-hold 检查 + 语言陷阱检查）
同时确认，随后横向核查发现全部 22 个同族函数无一幸免。

## 决定

方案 B（详见全文）：
1. 新增独立自由函数 `snapshot_compact_adjacency(&GraphTopologySnapshot) -> ([u128; MAX_NODES], usize, usize)`。
2. 22 个 wrapper 改为 snapshot 模式；`_inner` 从 `&self` 方法改为接收
   `&GraphTopologySnapshot` 的私有 `fn`。
3. 每个函数体里重复 ~25 行的邻接构造块替换成一行调用，算法本体不动。
4. 顺带修掉已发现的 6+ 处逐字重复代码。
5. 更新 `gos-topology-snapshot-pattern` skill，让下一次自动强化循环生成
   `topo23+` 时自然沿用正确模式——不靠人工提醒，靠"代码库里唯一存在的可
   复制范例"来固化正确性。这是"涌现式设计"在本项目里的一次具体落地。

## 现状

- 提案阶段，尚未实施。
- 撰写本笔记时，`topo22`（V3.32 之后的下一轮）已在工作区未提交，用的还是
  旧模板——是修复它成本最低的时机。
